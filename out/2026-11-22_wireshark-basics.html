Wireshark 입문: 패킷 캡처와 필터로 내 네트워크 들여다보기

"인터넷이 느린데 뭐가 이렇게 많이 통신하지?", "이 프로그램은 어디로 접속하고 있을까?" 하는 궁금증은 패킷을 직접 보면 풀립니다. 이 글에서는 무료 패킷 분석 도구 Wireshark를 처음 쓰는 분을 위해 설치부터 캡처, 필터, 실전 분석 예시까지 순서대로 정리합니다.

1. Wireshark는 무엇이고 언제 쓰나

Wireshark는 네트워크 인터페이스를 지나가는 패킷을 잡아서(capture) 사람이 읽기 좋게 계층별로 풀어 보여 주는 도구입니다. 보안 실무에서는 이럴 때 씁니다.

  • 악성코드 의심 PC가 어느 IP/도메인과 통신하는지 확인
  • 평문(HTTP, FTP, Telnet)으로 계정 정보가 오가는지 점검
  • 네트워크 장애 원인(재전송, DNS 실패, 연결 거부) 파악
  • 침해사고 분석 시 저장된 pcap 파일 재분석
💡 정보보안기사 실기에서도 패킷 캡처 화면을 보고 공격 유형을 맞히는 문제가 자주 나옵니다. 화면 구성에 익숙해지는 것만으로도 큰 도움이 됩니다.

2. 설치와 첫 실행

  • Windows/macOS: 공식 사이트(wireshark.org)에서 설치 파일을 받습니다. Windows는 설치 중 캡처 드라이버 Npcap 설치를 함께 권장합니다.
  • Ubuntu/Debian: sudo apt install wireshark 후, 일반 사용자 캡처 허용 여부를 묻는 창에서 "예"를 고르고 sudo usermod -aG wireshark $USER → 재로그인.
⚠️ 비슷한 이름의 비공식 배포 사이트에서 받으면 악성코드가 섞여 있을 수 있습니다. 반드시 공식 사이트나 OS 공식 저장소를 이용하세요.

실행하면 첫 화면에 인터페이스 목록(Wi-Fi, 이더넷, Loopback 등)과 옆에 작은 트래픽 그래프가 보입니다. 그래프가 움직이는 인터페이스가 지금 실제로 쓰고 있는 것입니다.

3. 화면 구성 이해하기

영역내용볼 포인트
패킷 목록(위)번호, 시간, 출발지, 목적지, 프로토콜, 길이, 요약어떤 통신이 많은지 한눈에
패킷 상세(가운데)이더넷 → IP → TCP/UDP → 응용 계층 순서의 트리OSI 계층별 헤더 값
바이트(아래)16진수와 ASCII 원본평문 문자열 노출 여부

색상 규칙도 기억해 두면 좋습니다. 기본 설정 기준으로 검은 바탕/빨간 글씨는 TCP 오류(재전송 등), 연한 보라는 TCP, 연한 파랑은 UDP/DNS 계열입니다(색 규칙은 View → Coloring Rules에서 확인·변경 가능).

4. 캡처 필터 vs 디스플레이 필터

가장 많이 헷갈리는 부분입니다.

구분캡처 필터디스플레이 필터
적용 시점캡처 시작 전캡처 중/후 언제든
문법BPF(tcpdump와 동일)Wireshark 전용
예시host 192.168.0.10 and port 53ip.addr == 192.168.0.10 && dns
특징저장 용량 절약, 버린 패킷은 복구 불가원본은 그대로, 보기만 거름

처음에는 캡처 필터 없이 잡고 디스플레이 필터로 거르는 방식을 추천합니다. 놓친 패킷을 다시 볼 수 있기 때문입니다.

5. 꼭 외워 둘 디스플레이 필터 12개

ip.addr == 192.168.0.10          # 특정 IP가 출발지 또는 목적지
ip.src == 10.0.0.5               # 출발지만
tcp.port == 443                  # 특정 포트
dns                              # DNS만
http.request                     # HTTP 요청만
http.request.method == "POST"    # POST 요청(로그인 폼 등)
tcp.flags.syn == 1 && tcp.flags.ack == 0   # 연결 시도(SYN)만
tcp.analysis.retransmission      # 재전송(네트워크 품질 문제)
tls.handshake.type == 1          # TLS Client Hello
tls.handshake.extensions_server_name contains "example"  # SNI로 접속 도메인 확인
frame contains "password"        # 원본에 문자열이 포함된 패킷
!(arp || dns || mdns)            # 잡음 제외

필터 입력창이 초록색이면 문법이 맞고, 빨간색이면 틀린 것입니다. 패킷 상세 영역에서 원하는 필드를 우클릭 → Apply as Filter를 누르면 필터 문법을 몰라도 자동으로 만들어 줍니다.

6. 실전 예시: 평문 로그인과 수상한 접속 찾기

6-1. 평문 계정 노출 확인

테스트용으로 본인이 만든 HTTP 로그인 페이지(또는 공개 연습 사이트)에 접속해 로그인한 뒤 http.request.method == "POST"로 거릅니다. 해당 패킷을 우클릭 → Follow → HTTP Stream을 누르면 아이디와 비밀번호가 그대로 보입니다. 이것이 "HTTPS를 써야 하는 이유"를 눈으로 확인하는 가장 확실한 방법입니다.

6-2. 이 PC는 어디와 통신하나

메뉴 Statistics → Conversations(대화 통계)와 Statistics → Endpoints를 열고 바이트 수 기준으로 정렬하면, 많이 통신한 상대가 위로 올라옵니다. 모르는 IP가 상위에 있다면 dns 필터로 어떤 도메인을 조회했는지, tls.handshake.extensions_server_name으로 어느 사이트에 접속했는지 확인합니다.

6-3. 포트 스캔 흔적

짧은 시간에 한 출발지에서 여러 포트로 SYN이 쏟아지고 대부분 RST로 돌아온다면 포트 스캔을 의심합니다. tcp.flags.syn == 1 && tcp.flags.ack == 0 필터 후 Statistics → Conversations의 TCP 탭을 보면 패턴이 뚜렷하게 드러납니다.

7. 주의할 점(법·윤리·개인정보)

  • 본인 장비, 본인 네트워크, 또는 서면 허가를 받은 환경에서만 캡처하세요. 타인의 통신을 몰래 캡처하는 것은 통신비밀보호법 등 위반 소지가 있습니다.
  • 공용 Wi-Fi에서 남의 트래픽을 잡는 연습은 하지 마세요.
  • 캡처 파일(pcap)에는 쿠키, 세션 토큰, 내부 IP 등 민감 정보가 들어 있을 수 있습니다. 블로그·커뮤니티에 올릴 때는 반드시 마스킹하세요.
  • HTTPS 내용은 기본적으로 암호화되어 보이지 않습니다. 본인 브라우저의 키 로그(SSLKEYLOGFILE)로 복호화하는 방법이 있지만, 학습 목적·본인 트래픽으로만 사용하세요.

8. 정리와 다음 단계

단계할 일
1공식 사이트에서 설치, 사용 중인 인터페이스 선택
2필터 없이 1~2분 캡처 후 정지
3디스플레이 필터로 dns, http, tls만 차례로 보기
4Statistics → Conversations로 많이 통신한 상대 확인
5Follow Stream으로 하나의 대화 전체 흐름 읽기

다음 글에서는 내 네트워크에 어떤 포트가 열려 있는지 직접 확인하는 nmap 기초를 다룹니다. Wireshark를 켜 둔 상태에서 nmap을 실행해 보면 스캔이 패킷 수준에서 어떻게 보이는지 함께 관찰할 수 있습니다.
