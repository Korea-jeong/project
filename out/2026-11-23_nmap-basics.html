nmap 기초: 내 PC와 공유기에 열린 포트 직접 점검하기

"포트가 열려 있다"는 말은 그 번호로 들어오는 접속을 받아 주는 프로그램(서비스)이 있다는 뜻입니다. 쓰지 않는 서비스가 열려 있으면 그만큼 공격받을 문도 많아집니다. 이 글에서는 무료 네트워크 스캐너 nmap으로 내 장비에 열린 포트를 확인하고, 결과를 읽고, 필요 없는 포트를 닫는 과정까지 정리합니다.

⚠️ 스캔은 반드시 본인 소유 장비나 서면 허가를 받은 범위에서만 하세요. 남의 서버를 허가 없이 스캔하면 정보통신망법 등에 따라 문제가 될 수 있고, 회사 네트워크라도 보안팀 승인 없이 하면 안 됩니다.

1. 포트와 서비스, 왜 점검해야 하나

포트대표 서비스외부에 열려 있으면 생길 수 있는 위험
22SSH무차별 대입(비밀번호 추측) 공격 대상
23Telnet계정·명령이 평문으로 전송
80/443HTTP/HTTPS웹 취약점 노출, 관리 페이지 노출
445SMB(파일 공유)과거 대규모 웜 확산에 악용된 사례
3389RDP(원격 데스크톱)랜섬웨어 침투 경로로 자주 언급

포트 점검의 목적은 "열려 있어야 할 것만 열려 있는지" 확인하는 것입니다.

2. 설치

  • Windows/macOS: 공식 사이트(nmap.org)에서 설치 파일을 받습니다. GUI가 필요하면 함께 제공되는 Zenmap을 쓸 수 있습니다.
  • Ubuntu/Debian: sudo apt install nmap
  • 설치 확인: nmap --version

3. 내 IP와 점검 범위 정하기

먼저 무엇을 스캔할지 정합니다.

# Windows
ipconfig
# Linux/macOS
ip addr        # 또는 ifconfig

예를 들어 내 PC가 192.168.0.23이고 공유기(게이트웨이)가 192.168.0.1이라면, 우리 집 내부망은 보통 192.168.0.0/24(0~255)입니다. 이 범위 안의 내 장비들이 점검 대상입니다.

4. 꼭 알아야 할 기본 명령

nmap 192.168.0.1                 # 자주 쓰이는 1,000개 포트(TCP) 스캔
nmap -sn 192.168.0.0/24          # 포트 스캔 없이 살아 있는 장비만 찾기
nmap -p 22,80,443 192.168.0.23   # 지정 포트만
nmap -p- 192.168.0.23            # 전체 TCP 포트(1~65535), 시간이 오래 걸림
nmap -sV 192.168.0.23            # 열린 포트의 서비스 이름·버전 추정
sudo nmap -sS 192.168.0.23       # SYN 스캔(관리자 권한 필요)
sudo nmap -sU --top-ports 20 192.168.0.1   # 주요 UDP 포트(느림)
nmap -oN result.txt 192.168.0.1  # 결과를 파일로 저장
💡 처음에는 -sn으로 장비 목록을 보고, 모르는 장비가 있으면 그다음 -sV로 자세히 보는 순서가 좋습니다. 집에 연결된 장비 수가 예상보다 많다면 Wi-Fi 비밀번호 유출을 의심해 볼 수 있습니다.

5. 스캔 방식 이해: TCP Connect vs SYN 스캔

구분TCP Connect(-sT)SYN 스캔(-sS)
권한일반 사용자 가능관리자(root) 필요
동작3-way handshake를 끝까지 완료SYN 보내고 SYN/ACK 오면 RST로 끊음
특징대상 로그에 접속 기록이 남기 쉬움빠르고 흔히 쓰이는 기본값

정보보안기사 실기에서는 스캔 방식별 패킷 흐름(SYN → SYN/ACK → RST 등)을 묻는 문제가 나올 수 있으니, 지난 글의 Wireshark를 켜 두고 두 방식을 각각 실행해 차이를 직접 확인해 보세요.

6. 결과 읽는 법

PORT     STATE    SERVICE  VERSION
22/tcp   open     ssh      OpenSSH 8.x
80/tcp   open     http     lighttpd
445/tcp  filtered microsoft-ds
8080/tcp closed   http-proxy
상태의미
open서비스가 접속을 받고 있음 → 꼭 필요한지 확인
closed도달은 하지만 받는 서비스 없음
filtered방화벽 등에 막혀 응답이 없음
open\filtered응답이 없어 열림/차단을 구분 못 함(UDP에서 흔함)

VERSION 정보는 추정이라 틀릴 수 있습니다. 버전이 보이면 해당 제품의 공식 보안 공지에서 현재 지원 버전인지 확인하세요.

7. 발견 후 조치: 닫거나, 막거나, 업데이트

  1. 필요 없는 서비스는 끈다: Windows는 "서비스" 관리 도구, Linux는 sudo systemctl disable --now 서비스명.
  2. 필요한 서비스는 접근 범위를 줄인다: 방화벽으로 내부망에서만 허용(Linux ufw allow from 192.168.0.0/24 to any port 22).
  3. 공유기 설정 점검: 포트포워딩·DMZ·UPnP가 켜져 있으면 내부 포트가 인터넷에 노출될 수 있습니다. 쓰지 않으면 끄세요.
  4. 업데이트: 공유기 펌웨어, NAS, OS를 최신으로 유지합니다.
  5. 다시 스캔해 확인: 조치 후 같은 명령으로 재확인하고 결과 파일을 비교합니다.
⚠️ 공유기 바깥(인터넷 쪽)에서 본 노출 상태는 집 안에서 스캔한 결과와 다릅니다. 외부 점검은 통신사·공유기 제조사 안내나 회사 보안팀 절차를 따르세요.

8. 정리

단계명령/작업
범위 확인ipconfig / ip addr
장비 찾기nmap -sn 192.168.0.0/24
포트 확인nmap -sV 대상IP
조치서비스 중지, 방화벽, 공유기 포트포워딩 해제
재확인같은 명령 재실행, 결과 비교
